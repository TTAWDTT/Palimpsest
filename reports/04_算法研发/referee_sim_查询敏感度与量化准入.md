## 原始发现及校正

### H1：null AUC 的解释

初稿写“后续真标签标定可能产生类别排序”。源码只把一项全局 threshold 从所有分数中减去，没有按类变换、方向翻转或再训练；这一操作不会产生新的排序。独立分数核对得到 Chimera 原图 null AUC=`2707/2880`=`0.9399305555555556`，并与收据一致，因此错误在因果解释而非数值。当前文字已经说明标定影响 BA、不能解释 AUC；本轮没有查明高 AUC 的原因，也没有选择 null 或按该 AUC 变更部署方向。

### M1：3.285 秒的范围

初稿把 3.285 秒写作标定、保存／评分、bootstrap 和结果处理阶段，容易使读者以为不含拟合。`run_iteration.py` 的总 start 在四头循环前，`elapsed_s` 在循环结束并保存 scores 后计算，所以 3.2852729 秒包含四次 fit；它不包含较早的输入读取，也没有测最终 iteration JSON 写出。当前正文已加入“包含这些 fit”，数值与原收据没有变化。

准备代理 8.953678349 秒确实低估完整准备 18.541684 秒。源码只对选中 raw／JPEG 行做 1792 项 float 转换与数组构造，而漂移计时在转换之后；小试把完整 CSV 遍历当固定成本再扩漂移函数，没有随选中行数扩这些转换。主报告已明确废弃代理，同时保留原值与实际值，故这项计算范围已有准确答案；0.7967965 秒只属于累计漂移函数。

### M2：source 最大下降的并列项

独立整数核对得到两项同为最大 BA 下降 `1/16`：`chimera/church/original>lg_blackfly/raw` 与 `chimera/horse/original>mac_iphone/raw`。两项各有 80 来源、REAL／FAKE 各40，类别正确率变化均为 `−3/40`／`−1/20`；church 来源翻转 `21/80`=26.25%，horse 为 `31/80`=38.75%。初稿所展开 church 的数值正确，但“source 最坏为 church”易让读者以为唯一最大值；当前正文已写出并列、各自翻转率，并明确所给 bootstrap 区间只属于展开的 church 项。并列项无需新运行，已有分数和收据均支持该修正。

全部四头各有1260条唯一且有限的 selection 分数，与两坐标 features 的 filename／来源／类别／条件逐项覆盖一致。features 共6300查询，fit／threshold／selection 为3780／1260／1260行、1260／420／420来源，来源角色不相交，每个来源有三个原生条件。独立脚本检查了当前执行源码 pins 和收据 SHA256；它没有重新证明20160行父缓存的所有数值，而是核源码的同-query配对规则及已有父缓存遍历收据。父处理规则以 filename 配 raw 与自身 JPEG 并要求所有 IDENTITY_FIELDS 相等，故没有把原图与拍屏的来源配对差当作推理特征。
