# 平坦背景频谱审计：尚不能从 RAW 反推 Raw2Event 屏幕格距

日期：2026-09-25。承接[新来源相位外推](Raw2Event新来源Bayer相位外推核验_2026-09-25.md)：当前前向模型把 CIFAR-10 的 32×32 输入放大到**假定**的 192×192 显示格点，但没有真实屏幕输入帧或像素尺寸。本次只试图从真实 RAW 的近似平坦区域找一个可复核的栅格约束；若证据不足，就不能把 192 改写成实测值。

从七段已验签录像的第 0 帧，固定取 RAW 传感器坐标 `y=8:112, x=32:660` 的画面上方区域。该区域在已看过的样本中位于 CIFAR 小图和 Tag 上方，但未有真实屏幕掩码保证每个像素都完全平坦。按 Bayer 的四个坐标子格分别隔 2 像素抽取，减去平滑背景，再对水平方向残差作加窗频谱；没有针对每张图调整 ROI 或峰搜索范围。

结果：七段中同一个坐标子格 `(偶行, 奇列)` 的最高水平峰都落在 **0.248–0.252 周期／子格像素**，相对分析频带中位功率仅 **2.1–2.8 倍**。另外三个子格的最高峰并不一致，例如 `(偶行, 偶列)` 在部分早日期图约 0.048，晚日期图则从 0.086 到 0.261 不等。一个固定坐标子格上的弱峰不能唯一解释为屏幕像素：Bayer/固定模式噪声、FFV1 编码前的 RAW 处理、行列读出及屏幕栅格都可能贡献周期结构。

又在 airplane 和 ship 两段中取第 0、79、159、238 帧，保持**同一个传感器坐标 ROI**，测 `(偶行, 奇列)` 约 0.25 峰的复数相位。airplane 的 AprilTag 中心从首帧 `(442.75,343.75)` 到第 159 帧 `(456.0,290.25)`，而该峰相位从约 −2.97 到模 $2\pi$ 后约 −3.24 弧度；ship 对应中心从 `(463.25,339.0)` 到 `(492.0,285.0)`，相位约 −2.62 到 −2.04。画面几何明显变化，峰在固定传感器坐标的相位却未随之给出可直接换算的屏幕格距；ship 的变化也不允许把它简单断言为纯传感器固定模式。这只是**排除草率物理归因**，不是判定该峰的真实来源。

因此，当前没有可由这 7 段首帧和 2 段时序独立测得的显示栅格尺寸、方向或子像素顺序；前向模型的 **192 显示格点继续标记为假设**。更可靠的测量需要作者实际显示缓冲区/屏幕分辨率与物理尺寸，或拍摄已知周期条纹及平场并记录几何、焦点和曝光的受控序列。这里的 RAW 频谱不能替代这些校准数据，也不能用一个峰解释 RRDataset 或手机拍屏的莫尔纹。

复算：

```powershell
python -m experiments.screen_capture.cfa_phase.raw2event.run_flat_field_grid
python -m experiments.screen_capture.cfa_phase.raw2event.run_grid_phase_motion
```

固定 ROI、各子格峰和逐帧相位在 `work/raw2event_flat_field_grid_probe.json`、`work/raw2event_flat_field_phase_motion.json`，相关脚本在同目录。报告中的周期是**每个隔 2 取样后的 CFA 子格像素**的频率，不能直接写成传感器像素或显示像素的节距。
