# 拍屏空间链：第一个可证伪的前向模拟原型

**后续更新：**本页记录首版历史状态。透视、可选 PWM/逐行曝光、分块大图渲染和单图 CLI 已在[第二阶段报告](Simulation第二阶段_透视时间链与可运行渲染_2026-09-24.md)实现；下面“目前没有实现”的列表应按此更新理解。

2026-09-24。**状态：物理结构原型，尚未经真实设备校准或外部拍屏数据验证。**本文记录实现范围、先验预测和下一道证据门槛。它不提供新的来源判别准确率，也不声称已完成完整 simulation。

## 为什么现在可以开始实现

前期[机理深读](../01_原理与协议/Simulation过程物理深读_屏摄与印刷成像_2026-09-24.md)明确了屏幕发光格点、投影几何、镜头低通、传感器取样、RAW 噪声、ISP 的顺序；[采集协议](../../../docs/controlled_screen_capture_protocol.md)给出改变距离、角度、对焦、曝光的可证伪测试。现有 RRDataset 缺逐张设备和物理方式标签，不能用其最终 JPEG 反推真实拍屏参数。UHDM 的真实配对档案尚未成功取得、公开论文讨论的是已配准图。因此我们先实现一个**小而可拆解**的空间链，以验证程序是否遵循这些结构约束，同时准备真实采集；不把合成与 RR 的接近程度当物理正确性的证据。

## 已实现的因果顺序

入口是已知的屏幕数字帧 `x` 和一个从传感器连续坐标映到屏幕像素坐标的**正对缩放与平移矩阵** `H`。先将每个输入像素按 `display_gamma` 转为简化的线性发光，并在**竖直 RGB 子像素**与填充率上构成连续屏幕格点；再把格点投影到过采样的虚拟传感器平面。每个细采样单元对矩形发光区域做面积积分，以避免点采样把数值混叠误认为拍屏莫尔纹。之后按传感器像素单位施加高斯光学模糊，在每个传感器像素内积分。所得三通道辐照度通过 RGGB Bayer 掩模取样，在该位置加入信号相关 Poisson 噪声和 Gaussian 读出噪声，最后用简单双线性去马赛克及标准 sRGB 曲线生成未编码图。

公式层面的主干是：

`u = H(s)`, `L(s) = E_subpixel(x, u)`, `I = integrate_pixel(PSF * L)`, `RAW = CFA(I) + shot + read`, `y = ISP_basic(RAW)`。

实现保留 `irradiance`、`noiseless_mosaic`、`raw_mosaic` 和 `srgb` 四种中间输出，便于未来拿真实 RAW 分段检验。代码位于项目 `origin_simulation/screen_capture.py`；八个回归测试位于 `tests/test_screen_capture.py`。`pyproject.toml` 和 `uv.lock` 固定了运行依赖。项目根目录执行 `uv sync --extra dev` 与 `.venv\Scripts\python.exe -m pytest tests/test_screen_capture.py -q` 可复核。

## 当前可通过的结构测试

| 测试干预 | 预先固定的预测 | 本机状态 |
|---|---|---|
| 仅改变 `H` 中的屏幕像素/传感器像素尺度 | 模拟屏幕格点的主频应随投影尺度改变 | 自动测试通过；此处只验证模型内部约束。 |
| 保持 `H`，增加光学模糊 | 格点能量应下降，主频不应随机移动 | 自动测试通过。 |
| 保持噪声尺度，改变数字帧亮度 | Poisson RAW 残差方差应在亮部较高 | 自动测试通过；不是相机实测噪声曲线。 |
| 固定随机种子与输入 | RAW 可逐值复现，所有中间量形状与数值有限 | 自动测试通过。 |
| 均匀白屏，改变数值积分倍率与相位 | 三通道均值应收敛至填充面积的解析值；倍率不足须拒绝运行 | 自动测试通过；这是数值正确性，不是实拍验证。 |
| 固定满阱容量，改变曝光电子数 | 未饱和信号应随曝光变化 | 自动测试通过。 |
| 从零曝光增加到正曝光 | 零曝光的预期光电子为零；有读噪时 RAW 仍可非零 | 自动测试通过。 |
| 不合法参数或积分精度不足 | 明确拒绝非有限参数与欠采样条件 | 自动测试通过。 |

这些测试只说明代码实现了预设机制，**不是**“生成图像已经像真实拍屏”的实验。此前 RR 再数字化的统计原型在真实/合成二样本测试仍有 AUC 0.946–0.964，说明单靠频谱外观调节不能代替验证物理过程。

## 参数解释及当前缺失

| 参数/机制 | 当前含义 | 获得真实解释所需证据 |
|---|---|---|
| `sensor_to_display` | 虚拟正对缩放与平移；**目前拒绝透视、旋转和斜拍**，以便准确积分矩形子像素。 | 同一设备的屏幕四角、拍摄距离、焦距、未裁切真实照片；扩展斜拍前需验证非轴对齐格点的数值积分。 |
| 竖直 RGB 条与 `fill_fraction` | **一种屏幕布局假设**，并非所有 LCD/OLED 的通用子像素结构。 | 实际屏幕的显微照片或设备资料；不同面板应分别建模。 |
| `display_gamma` | 简化的每通道发光曲线；不能叫设备真实 gamma。 | 固定视角、RAW/手动曝光下的灰阶和彩色色块。 |
| 高斯 PSF | 光学低通的可调复合近似；尚无镜头像差、景深和像场变化。 | 斜边/点源或格点在多个对焦位置的 RAW 测量。 |
| Poisson + Gaussian RAW 噪声 | 信号相关噪声的基础模型；`exposure_electrons_per_unit=None` 是无噪声中间图预览，数值 `0` 则是真正的零光子曝光，仍可有读噪。曝光转换与满阱容量已分开。 | 同一亮度的重复 RAW、黑场与曝光序列，估计增益和读噪。 |
| 双线性去马赛克 + sRGB | 仅用于得到可看输出；不代表实际手机 ISP。 | 相机 RAW/JPEG 同拍配对、白平衡/色彩矩阵/锐化等记录。 |

目前**没有实现**：透视/旋转/斜拍、屏幕光谱与视角响应、PWM/滚动快门时间积分、真实镜头畸变和反光、真实相机 ISP、平台 JPEG、打印/扫描/投影。这些应分别由可测数据驱动，不能为了逼近 RR 的最终图而直接给结果叠纹理。当前实现只处理小图块，过采样总量设有上限；不是可用于大规模训练的高速模拟器。

## 下一道证据门槛

优先进行[受控拍屏采集](../../../docs/controlled_screen_capture_protocol.md)：同一屏幕/相机/数字帧，在已记录距离与对焦条件下保留未裁切 RAW + JPEG 和屏幕四角。**先验证格点投影频率与几何尺度的联动、离焦时峰强的变化，以及弱/无莫尔纹条件的覆盖**；再校准颜色、噪声和时间链。校准图与验证图、设备/会话须分开。真实图与模拟图对比时统一裁切和末次编码，并加入简单缩放+JPEG及后期叠纹理对照。

如果无法取得这种带控制量的照片，代码可以作为机制假说和生成可视化示例，但不能升级为“真实物理过程已验证”的 simulation，也不应直接用其训练最终来源检测器并声称对真实传播稳健。RR 的冻结 `reserved` 可作同包事后对照，不构成外部干预验证。
