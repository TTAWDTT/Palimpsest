# 波动光学拍屏快速路径：从裁块走向较大画幅的分块计算

2026-09-25

## 原有瓶颈

`wave_prefilter` 已在[中等失焦](波动光学拍屏快速前滤波的数值边界_2026-09-25.md)和[高光圈精确对焦](高光圈正对拍屏的光学裁块边界与快速积分_2026-09-25.md)的受限虚拟参数中核过采样前积分，但以前必须先把**整个**显示画面展开为每轴 12 子格的发光栅格。512×512 显示帧需要 `512²×12²≈3775 万` 个发光子格，超过代码设置的 1200 万子格门限，不能运行。这是计算内存问题，不是物理模型已达到更大图像保真。

## 分块方法

保持已有的顺序：显示矩形发光面积覆盖 → 同一理想波动光学 PSF → 传感器面积积分 → 后续时间、光谱、RAW/ISP。对轴对齐投影，把传感器输出切成方块；每块反投影到显示平面，向四周加入该光学核的**完整有限支撑**及插值余量，裁出显示像素并重算局部发光栅格。对局部坐标平移投影矩阵，完成光学卷积和传感器积分后仅保留本块输出。显示画面之外仍按零辐照处理。每块都按展开子格数验证 1200 万门限，超限会要求更小 `tile_size_sensor_pixels`。

现在小图默认仍用整幅栅格；超出门限时默认自动用 128 传感器像素方块，也可以在 `render_screen_capture`、`run_screen_pipeline` 或 JSON CLI 配置中明确给 `tile_size_sensor_pixels`。其余物理适用边界不变：仍只允许已测的正对轴向、中等失焦或高衍射精确对焦两类理想场景；不能用分块选项绕过失焦、波长或投影拒绝条件。

## 核验

在中等失焦和 f/13 精确对焦两种虚拟设置中，用 72×72 随机显示帧比较整幅与 8 像素传感器分块，逐像素误差低于自动测试阈值 `2×10^-6`。另取 300×300 显示帧触发自动分块，与其同源 72×72 裁切的整幅路径对比，数值一致。单图 CLI 的显式 8 像素分块也通过冒烟测试。

更大的压力检查在本机上把 512×512 虚拟显示帧渲染为 512×512 传感器输出，采用 f/13、完全对焦、理想圆瞳孔和每屏格约 1.3272 传感器像素的**虚拟**设置。自动分块整幅运行一次为 **4.02 秒**；另在相同来源的 192×192 显示裁切上做 160×160 整幅参照。两者公共 160×160 区域的平均辐照度绝对差为 `1.16×10^-8`、最大差为 `1.04×10^-7`；穿过 128 像素分块接缝的局部最大差为 `7.45×10^-8`。逐项结果在 `work/wave_prefilter_tiled_benchmark.json`，程序在 `work/benchmark_wave_prefilter_tiled.py`。这是单机一次计时，不等于稳定吞吐，更不代表手机实时速度。

这里验证的是**分块与整幅数值实现一致**，没有因此增加现实拍屏过程的证据。当前 PSF 是理想圆瞳孔，显示子像素、镜头像差、曝光与 RAW/ISP 仍未校准；512 方图也不是典型手机整幅分辨率。未测过该分块输出对固定来源检测器分数或真实拍屏匹配的影响。下一步在独立真实拍屏配对上检查不同内容、投影位置与边缘条件，随后才考虑将其用于大规模合成。

验证：中等失焦、高衍射聚焦、超整幅门限自动分块三项数值回归及单图 CLI 分块冒烟通过；全仓库 `python -m pytest -q` **79 项通过**。
