# 真实拍屏受控数据再检索（2026-09-24）

## 结论

找到了**可以推进部分物理验证**的现成数据，尤其是 DeepMoiréFake 的条件标签、RawVDemoiré 的实拍 RAW/sRGB 对，以及已验证可按名配对的 Dragotti LCD 再拍档案。但截至本轮核查，仍没有确认到一个**可直接取得、对同一数字图系统扫描距离×角度×对焦×曝光、保留未裁切照片/RAW及逐张精确参数**的公开集。故应把各数据按可识别的物理环节组合使用；公开数据不能替代最终的最小受控采集。

这里的“可用”分三级：A 是本机验证到真实图像字节，B 是官方发布下载入口但尚未核到包内文件，C 是需要申请/尚未发布。不要把论文中“采集时变化过参数”误写成“逐张参数已发布”。

## 决定怎样使用这些数据

### RawVDemoiré 官方网盘目录的只读核验

使用官方分享链接及公开提取码，经 `pan.baidu.com/share/verify` 得到 `errno=0`，再经 `pan.baidu.com/share/list` 读取根目录及 `train/`、`test/`。根目录确有 `train/`、`test/`、`nets/`。测试集四包：`moire_rgb.zip` 5,195,595,082 字节、`moire_raw.zip` 4,280,342,894、`gt_rgb.zip` 2,987,610,063、`gt_raw.zip` 4,656,478,645。`train/` 相应四包共 89,866,616,491 字节；训练和测试八包合计 **106,986,643,175 字节（99.64 GiB）**。如果只验证真实拍屏 RAW、其 sRGB 与数字目标，测试集前三包共 **12,463,548,039 字节（11.61 GiB）**；`gt_raw` 是伪真值，不必优先取。以上是云端目录元数据，**并非下载成功、ZIP 完整性或内部配对的证明**。

继续用同一匿名分享会话对测试 `gt_rgb.zip` 试行单文件 `api/sharedownload`，返回 `errno=2`，未给出可用下载链接。该请求可能缺当前网页的签名/登录参数；**一次失败不能证明该包必须登录、已失效或永远无法下载**。作者仓库本轮未发现 Google Drive/HTTP 镜像，不能把已核目录升级为“文件可取”。此处没有使用用户账号、绕过访问限制或生成本地 ZIP。

1. **物理子链：**以 VD_raw 为优先获取目标，先核包内是否能形成 `显示源帧 → moire_raw → moire_rgb` 的稳定映射。其 RAW 仅是真实拍屏端，`gt_raw` 必须标成伪真值。用屏幕几何、CFA 采样、RGB 后频谱的条件一致性评估模型；不能只比较单一 FID 或“看上去像”。
2. **角度和设备干预：**DMF 最值得继续追踪。先依据公开论文定义可检验的条件对，例如同源视频、相同手机/显示器/光照下正面与左右角度的透视、格点方向、莫尔纹峰频变化；拿到实包后先审计完整交叉和逐样本元数据，再执行。不能从 12,832 的乘式推断角度也完整交叉。访问受限，当前只完成公开 API 审计，没有代表用户提交申请。
3. **独立结果检验：**Dragotti 的实际一对图像已经证明公开档案内存在可用的真实再拍配对；完整包下载及逐图审核后，可在固定设备组之间做观察性外测。RRDataset 继续仅用于其已冻结的同包目标任务验证，缺少逐图物理路线和设备，不能承担机制校准。
4. **仍需自采的最小量：**要声称“模拟能正确预测距离/角度/对焦/曝光变化”，至少对同一数字源、同一屏幕与相机做有标尺和原始文件的受控变化。`docs/controlled_screen_capture_protocol.md` 已列采集与否证规则。公开数据可减少校准盲区，却没有替代这一项。

## 核查边界

- Dataverse 数量、体量及 restricted 状态来自上述官方 API 于 2026-09-24 的只读查询，**不是**档案内容验证。
- 本轮没有发申请、下载约 199 GiB 的 DMF，也没有称它适用于静态全图 AI 来源检测。
- 本轮没有新增模拟参数或训练模型。接下来按“能观察什么物理量”选择数据，避免先调拟合参数再寻找支持它的数据。
