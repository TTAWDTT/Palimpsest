## 能验证什么，不能验证什么

1. **能验证：**同一数字来源图经历两套真实屏幕/相机采集后的固定来源检测器分数和错误翻转，以及尺寸、颜色、频谱变化。它是 RR 发布包之外的真实物理传播数据，适合检验模拟训练是否只贴合 RR 的发布习惯。
2. **不能验证对焦参数的预测：**归档五个顶层组只区分原图、两设备的普通再拍及对抗再拍；成员路径里无 focus 标签。抽查三个主组 PNG 无内嵌元信息键。论文的四档对焦图表有设备级实测意义，但**本发布包没有足以复算逐图对焦曲线的标注**。
3. **不能直接当作“全类型 AI 图”基准：**发布集只有这三类内容和 StyleGAN2 生成器；原图 256×256，拍屏图已裁成固定正方形，分辨率、设备与真假可能造成捷径。固定阈值成绩必须按原图、Mac、Monitor 及三种内容类别分层，同时报告原图与拍屏的同源分数变化。B-Free 预训练图像与本集是否近重复尚未审计。
4. **不能单独标定整个物理链：**没有实际显示帧、显示 RGB 光谱/子像素、镜头 PSF、RAW/ISP 参数和逐张曝光；即使模拟在最终 PNG 上相似，也不能唯一识别每个物理参数。作者对抗目录还包含主动优化显示图的额外因果路径，须与普通真实传播分开。

## 后续过程模拟的冻结划分

已在查看 B-Free 全量结果前，按来源 ID 的 SHA256 排序，在每个“猫/教堂/马 × 真实/生成”的 200 来源内固定 **40 校准、20 开发、140 保留**，合计 240/120/840 来源。每个来源的原图、Mac 与 Monitor 实拍始终在同一划分，避免同一内容跨划分泄漏。E 盘清单 `E:\ai_image_origin_research\data\manifests\chimera_simulation_source_split.csv` 的 SHA256 是 `4d429ea32644b2381e86cecd6c005261b842e7ca6905c3ff45769444afe01ebf`，生成规则在 `work/freeze_chimera_simulation_split.py`；保留集不用于调参。这里的“保留”只对本项目后续模拟器有效，**不能排除 Chimera 来源与现成检测器预训练集重叠**。

校准时仅估计同设备共用的可观测复合量，例如画面位置/尺度、低频色调、有效模糊和残差频谱；不把这些量命名为真实焦距、光圈或屏幕子像素结构。固定参数后，在开发与保留来源上同时比较真实拍屏和模拟拍屏的成对差异，并加入简易缩放+模糊/编码作为对照。由于公开包没有对焦或角度干预，此数据只可检查已发布的两个设备域及内容迁移，不能证明模型能预测未见的物理操作。

### 未使用保留来源的输出观测量

| 观测量 | Mac 校准 / 开发 | Monitor 校准 / 开发 |

仍只用 240 校准 + 120 开发来源，把两套实拍图缩至 256×256 后，以平滑灰度图对**每一对图分别**用 ECC 拟合 2D 仿射变换。720/720 对都得到在预定宽松范围内的变换（奇异值 0.8–1.2、平移绝对值不超过 24 像素、配准后灰度零均值相关不下降）。这个成功率仅说明发布后的原图/实拍图可以开展**逐对对齐的残差分析**；由于每对都用了目标图反向拟合，**不是**由模拟器预报的相机姿态或真正的屏幕投影。

### 固定几何之后的复合颜色响应

在同一个非保留划分上，又仅用每设备 240 张校准来源拟合一套共享 **3×3 RGB 矩阵 + 常数项**，输入是 256×256 原图，目标是经上述固定几何对齐后的 256×256 实拍发布图。拟合从各图去边框 16 像素的区域每隔 4 像素取样；开发集每个像素只评测一次，没有逐图调色。这里 RGB 是**已编码的 PNG 数值**，矩阵合并了显示响应、相机、ISP、裁切与再次缩小的作用，**不是相机颜色校正矩阵，也不是完整拍屏 simulation**。

| 设备，开发各 120 来源 | 不对齐/不调色 RGB MAE | 固定几何/不调色 | 固定几何+本设备颜色 | 错用另一设备颜色 |
|---|---:|---:|---:|---:|
| MacBook→iPhone | 0.10665 | 0.10574 | **0.06280** | 0.10055 |
| LG→Blackfly | 0.09077 | 0.06686 | **0.04911** | 0.09126 |

本设备颜色映射相对仅固定几何，在 Mac **112/120**、Monitor **108/120** 开发来源上降低 MAE。再做三个“留一个场景”的检查：从其余两场景的 **160 校准来源**拟合，测试没见过该场景的 **40 开发来源**；Mac 猫/教堂/马 MAE 分别 **0.06617/0.06157/0.06485**，Monitor 为 **0.05092/0.05046/0.04927**。跨设备误用使两套 MAE 都明显上升，说明简单共用一套 RGB 参数不足。但这些成绩是输出空间的**复合拟合**，像素误差下降不能证明屏幕子像素、镜头 PSF、RAW 噪声或 ISP 被正确模拟；下一步要在固定几何/颜色后分析剩余的锐度、频谱和随机纹理，且保留 840 来源不参与调参。脚本 `work/evaluate_chimera_composite_photometry.py`，逐设备系数和完整统计在 `work/chimera_composite_photometry.json`。

为检查 3×3 混色项是否真的必要，保持同一校准/开发划分再拟合两种更简单的映射。**共享单一 RGB 增益+偏置 / 每通道独立增益+偏置 / 完整 3×3+偏置**的开发 MAE，Mac 分别为 **0.06703 / 0.06666 / 0.06280**，Monitor 为 **0.05812 / 0.05393 / 0.04911**。完整矩阵确有额外拟合收益，但相对简单增益/偏置只减少约 0.004–0.009 MAE；现有数据不能据此认定存在特定的传感器通道串扰或屏幕光谱效应。更重要的下阶段问题是：剩余误差中的模糊、采样格、噪声和局部非线性是否能被**独立物理证据**约束。

同一冻结开发集上的残差定位显示，按原图 Sobel 梯度分位数选出各图最平坦/最强边缘的各 25% 像素后，Mac 的颜色校正残差 MAE 均值为 **0.0601/0.0735**（边缘为平坦区的 1.22 倍），Monitor 为 **0.0416/0.0639**（1.54 倍）。用开发图逐张后验最优仿射替代固定仿射，只把整体 MAE 从 **0.06280→0.06041**、**0.04911→0.04797**。这说明在此发布图/尺寸口径下，剩余差异不是简单地继续微调全局仿射就能消除；边缘相关残差值得优先追踪光学模糊、显示/相机重采样与局部 ISP。**它们同样可能来自未建模的局部几何或内容依赖颜色响应，不能单凭这一比值认定镜头 PSF。**全部逐图统计随 `work/chimera_composite_photometry.json` 保存。

据此做一个**负对照式的有效模糊实验**：在固定几何与颜色后，只许从预先列出的输出分辨率 Gaussian `σ∈{0,0.35,0.5,0.7,1.0,1.4,2.0}` 里，用各设备 240 张校准来源选一档，再锁定到 120 张开发来源。两设备都选 `σ=0.7` 个 **256×256 输出像素**；Mac 开发集平均 MAE **0.06280→0.05751**，114/120 图改善；Monitor **0.04911→0.04415**，120/120 改善，猫/教堂/马三个开发场景均改善。这说明一个共享的有效低通项确实解释了部分边缘残差。它发生在**已经缩小的、已编码 RGB 上**，其中包含 Lanczos、作者裁切、ISP 和相机/屏幕的共同作用；相同的 0.7 不说明两套镜头有相同 PSF，更不能作为物理镜头参数输入原生拍屏模拟器。机器记录 `work/chimera_effective_blur_proxy.json`，复算 `uv run python -m work.evaluate_chimera_effective_blur_proxy`。

然而，这条复合代理生成新图后，并未复现 B-Free 在真实拍屏上的同源分数跌幅和错误翻转；完整反证见[检测器迁移实验](Chimera拍屏复合代理的检测器反证_2026-09-25.md)。

固定 B-Free 官方权重在这 **3,600 张完整主清单**上的推理已完成、逐行验收；AUC、固定阈值正确率与同源变化另见[外部真实拍屏基线](../02_数据与基线/Chimera真实拍屏_B-Free外部配对Baseline_2026-09-25.md)，不把目录审计误写成算法精度。审计机器记录是 `work/chimera_archive_audit.json` 与 `work/chimera_extracted_audit.json`。
